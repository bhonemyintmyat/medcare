What this page will not do, and why

Four things you would expect to find here are missing on purpose rather than by omission. Some are real limits of a site with no server of its own; one is a limit of the act itself. Knowing which is which is faster than hunting for a button that was never built.

  • Create an account for somebody else. That needs Supabase’s auth.admin API, which only answers to the service_role key. That key can read and rewrite every table past every policy, so it belongs on a server or in nobody’s hands — never in a page anyone can open with DevTools. Do it in the Supabase dashboard, under Authentication → Users — and note that creating an account for somebody means choosing their password for them, which is rarely the kindest way to get them onto the site. Signup is.
  • Undo a deletion. Deleting an account is here now — the Delete button on each row — and it is the one action in the admin area with nothing behind it. No archive, no draft, no thirty-day window. The row goes, the sign-in goes, and their saved items go with it. What stays is everything they wrote for the site, with the author line blank. The dialog asks you to type the account’s name for exactly this reason.
  • Reset somebody’s password. This site has no password-recovery screen yet, so a reset email would land people on a page that cannot finish the job. Sending one from here would be worse than not offering it. Until that screen exists, the Supabase dashboard is the honest answer.
  • Rename somebody. A person’s name is theirs, and they can change it on their own profile page. The one exception is in each account’s Details panel: an admin may clear a display name that should not be on the site, which drops the account back to the name it signed up with.
